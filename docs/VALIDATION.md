# v0.0.1-beta 验收

发布程序包和支持包均已封存。87 个管理源码成员逐一与工作树比对一致；验收读取了 guest 实际运行 ELF 的散列。

| 检查 | 结果 |
| --- | --- |
| Python 管理、准入和打包回归 | 571 项通过 |
| 救援工具回归 | 25 项通过 |
| C++ 原生检查 | 正常构建与 ASan/UBSan 各 243 项通过 |
| 异常输入变异 | 两种原生构建各 10,000 次通过 |
| 正式程序包 + 支持包 | 四次启动的完整生命周期验收通过 |
| 原生停止与重新启用 | 忙消费者拒绝、锁占用拒绝、两次停止/重启用通过 |
| USB 故障与死亡接管 | 原工作进程及已打开文件恢复、SIGKILL 接管、异常重新启用拒绝通过 |
| GitHub Actions | 管理/打包检查和原生 release/sanitizer 检查通过 |

四次启动覆盖：安装与登记不激活、显式首次建图和启用、活动包重装不替换原执行者、包移除拒绝、忙设备拒绝、短断恢复及实际文件内容核对、持久停用重启、开机启用、正常移除、冷态卸载和重装。

工程验收使用隔离 guest 中的资格 fixture。只有该封存包的完整验收通过之后，才生成引用其报告的独立发布资格。正式验收重新安装了真实程序 `.deb` 和支持 `.deb`，`qualification_fixture=false`；没有把旧候选保存资格升级为激活资格。

实验使用普通文件作为 QEMU 磁盘、2 vCPU、3 GiB RAM，无 guest 网络、宿主块设备透传或共享目录。种子作为只读 backing，开始计算完整 SHA-256，结束核对 inode、大小及时间戳不变。实机部署、真实物理拔插、睡眠唤醒和根盘正式支持均未作为本发布验收。

前期多次启动曾因 cloud seed 的临时模块目录丢失参考材料而失败；修正的是观察器每次启动前提供已认证文件的流程，未放宽产品准入。一次原生实验的功能检查结束后，资源监测遇到 QEMU 删除 socket 的竞态而判失败；监测修正后已在独立目录重跑通过。早期失败产物保留在本地实验目录，最终证据单独封存。
