# v0.0.1-beta 支持与证据

公开入口限于 Ubuntu 24.04、x86_64、ext4、带非空 USB serial 和分区标识的独立数据分区，以及单路径 DM multipath。拒绝系统盘、swap、上层 DM 消费者及正在使用的裸分区。

内核必须提供 `DM_MPATH_PROBE_PATHS`（multipath target 至少 1.15.0），现有 no-path 超时必须满足数据准入预算。内核版本号本身不构成支持资格。

## 精确组合

发布资格位于独立支持材料中，绑定实际管理入口、管理清单、原生 ELF、RAM 包、依赖、官方内核镜像与模块。内核来源通过 Ubuntu 签名材料核验；当前运行 build ID 与文件材料关联。它信任本机 root 和内核，不是内存完整性证明。

首个验收目标为 `7.0.0-34-generic`；当前软件源另有较新的 HWE 包，因此不能把这个工程组合叫作“所有当前 HWE 都支持”。最终通过的组合及证据以本次 Release 附件为准。缺少匹配资格时，即使候选流程允许保存，也不能启用。

## 证据分层

| 证据 | 能说明什么 |
| --- | --- |
| 普通回归、sanitizer | 输入拒绝、状态机及内存问题的自动检查 |
| 安装包检查 | 所有权、权限、默认不激活与移除检查 |
| QEMU 生命周期 | 具体虚拟硬件与软件组合上的安装、启停、恢复和多次启动 |
| 真实硬件 | 需要另行核验 USB 控制器、供电、实际拔插、休眠等 |

v0.0.1-beta 不把历史 C++ 实机启动或旧 Python 实机短断结果作为本发布硬件验收。根盘保护、LVM、FAT/exFAT 的历史实验不属于新公开数据生命周期的首版承诺。

## 已知限制

- 原进程连续性只对具体实验工作负载验收，不保证所有应用都能忍受阻塞。
- 无法枚举所有可能的裸设备开放描述符，设备身份元数据可被克隆。
- 不修复已有文件系统错误，不撤销已向应用返回的失败，不保证掉电缓存安全。
- 不承诺永久 D-state 的取消或任意故障点的原子回退。
- 停用和移除保留本次 RAM 及锁；完整卸载可能需要先正常重启。
- 内核或依赖更新后需新的组合验收；没有自动放宽或静默降级。
