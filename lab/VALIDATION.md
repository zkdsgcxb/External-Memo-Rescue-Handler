# 虚拟 USB 根盘实验记录

日期：2026-09-23，Ubuntu 24.04 / Linux 6.8.0-139-generic，QEMU 8.2.2，KVM。全部实验在新建虚拟磁盘中执行，没有给 QEMU 透传宿主块设备，没有对宿主根卷做故障注入、刷新、暂停或修复。

## 发现并修复的恢复错误

初始实验稳定复现 `/dev/sda1` 重新枚举为 `/dev/sdb1` 或 `/dev/sdc1`，LVM 仍引用旧设备，身份核验成功但 `refresh` 拒绝合法线性 LV。

原因是 `lvs --segments --reportformat json` 的报告键为 `seg`，原代码读取 `lv`，得到空结果。模拟测试也错误地构造了 `lv`，因此未暴露问题。现已修正解析、修正模拟数据，并加入虚拟机采集的真实输出 fixture 回归；13 项恢复单元测试通过。

此修复已进入源码与新构建的实验 guest。**本轮未更新宿主已安装的救援包或其 RAM 副本**，部署仍需健康系统中的独立构建、安装和验证。

## 只读与用户态存活

普通持续写入组在断联期间出现 ext4 错误、journal 中止以及内核报告重新挂为只读。恢复没有执行 remount；`lvchange --refresh` 只更新映射。

增加文件系统探针的一轮中，映射和块读取已经恢复，`statvfs` 的只读标志却为 false，实际新文件写入仍返回 EIO，恢复后原工作进程又记录了 33 次失败。因此不能只凭 `rw` 标志或块读取成功，宣称文件系统或用户态恢复；也不能把这个结果简化为“现在只是只读挂载”。

预先暂停组在拔盘前就让 DM 挂起 I/O，重接、核验与刷新后放行。三组均保持同一个工作进程 PID 和启动时间，恢复后继续成功写入 31 / 30 / 32 次；新文件写入和 `fsync` 均成功，文件系统只读标志为 false，全部工作负载未记录 I/O 失败。最长单次写入分别约 1.32 / 2.05 / 2.41 秒：这是“暂停后继续”，不是零延迟。

这证明了一个有限命题：**在本实验的理想时序下，提前暂停 I/O 可以保住文件系统可写和同一个简单工作进程。** 尚未证明突发掉盘后才响应来得及、所有已有写入的持久性、桌面/数据库/网络会话完整存活，或长期重复掉盘稳定性。完整 Ubuntu/systemd/真实应用集成也未覆盖。

## 后续方向

优先研究预先建立的稳定块设备层，在路径消失时有界排队/重试，在严格确认同盘后重新接入。dm-multipath 的无路径排队机制可作候选，但需要先在虚拟机里验证单 USB 路径、超时与身份管理，不能直接改宿主根盘。

已经返回应用的 EIO 和已经中止的 journal 不会因为刷新映射而自动撤销；已经退出或因 SIGBUS 终止的进程也不会复活。完整用户态恢复应拆成进程仍在、I/O 成功、数据一致性和应用自身恢复四类验收。
