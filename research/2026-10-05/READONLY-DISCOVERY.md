上一轮只读联网核验确认对应 Ubuntu 官方软件包页面与归档可获取；普通用户可以通过发行版的官方 HWE 渠道获取，无须混用发行版、PPA 或自行编译内核。[Ubuntu 内核生命周期](https://ubuntu.com/kernel/lifecycle)、[noble-updates HWE 元包](https://packages.ubuntu.com/noble-updates/linux-generic-hwe-24.04)。仓库候选会变化，以上精确版本只是本次观察。

**`7.0.0-34` 是既有实验和本机基线，不是用户同意的公开最低版本或首发硬要求。** 不扩大恢复核心的可行首发方向是：Ubuntu 24.04 amd64、官方 HWE、逐个发布组合验收。此方向仍是建议，尚未成为发布承诺；本轮 JSON 明示 `public_support_policy=not_selected`，也没有将某个精确内核写进发现逻辑。

必要条件应按功能核对：本项目使用 Linux 6.16 引入的 `DM_MPATH_PROBE_PATHS`，现有 C++ 准入要求 multipath target 至少 `1.15.0`；还依赖 diskseq、`tmpfs,noswap`、systemd/cgroup，以及当前内核与冻结运行包/登记的匹配。普通数据维护现有准入要求全局无路径排队超时至少 10 秒，以容纳其 8 秒预算。接口出现不等于已通过本项目验收，也不能据此声称所有 Linux ≥6.16 可用。上游接口对照：[v6.15 头文件](https://github.com/torvalds/linux/blob/v6.15/include/uapi/linux/dm-ioctl.h)、[v6.16 头文件](https://github.com/torvalds/linux/blob/v6.16/include/uapi/linux/dm-ioctl.h)。

首发范围决定前仍有以下阻塞：

1. 要选定一个普通用户可获取的发行组合，用该组合重新构建并完成对应冷启动、根盘和数据盘验收。不能把本机或旧 QEMU 的 34 内核成果外推给 38。
2. 当前包、登记与内核精确匹配，既有根镜像升级流程要求同 ABI。跨 ABI 升级、保持可启动旧入口及相应回退，需要先有管理层生命周期方案和实验；不能让 HWE 自动升级悄悄越过验证边界。
3. 官方 GA 6.8 不具备目前所用的上游新接口；仅升级 Ubuntu 用户空间不能补齐内核 ioctl。本轮不增加旧内核适配，也不修改内核。
4. 包版本单调性、首次登记即生效、退出后重入等已知管理缺口仍待后续切片解决；只读发现不声称修复它们。

## 切片与复用

入口是现有 `manager discover`，中文编号选中只查看同一快照详情；`--json` 无提示，适合自动化。源码试读与未来可信包入口见 [管理说明](../../guard/MANAGER.md#先做只读发现与预检)。当前已安装旧入口未获得这个子命令。

新增 `guard/discovery.py` 负责一次性只读采样、关联和显示；`manage.py` 仅增加分发。`admin_entry.py` 与 `manage.py` 在导入项目代码前禁止生成字节码缓存。冷态 `admin/dm.py` 增加按已登记 UUID 查询表、同时核对返回名称与 UUID；保留旧按名称接口。

复用现有函数而不另造恢复状态机：

| 已有能力 | 本次用途 |
| --- | --- |
| `diagnostics.Reader` | 信任边界、大小限制、登记与收据读取 |
| `Collector.read`、`Collector.device` / `classify` | 将读取失败保留为未知，核对本次启动、systemd MainPID、事务 owner、事件、运行 ELF，并复读排除变化 |
| `Collector.manager_candidate`、`checksum`、`choice` | 提取可信候选记录与有限状态，不执行候选代码 |
| `admin.registry.validate_record` | 复用持久登记规范，拒绝含旧设备实例等不合法记录 |
| `admin.dm.expected_table` / `table_digest` | 比较既有登记 DM 表及底层设备；另检查排队特性仍启用 |
| `admin.data.CRITICAL_MOUNTS` / `unescape` | 系统挂载边界和内核转义解析 |
| `admin.identity.FILESYSTEM_TYPES` | 缓存提示使用现有 ext4/exfat/vfat 数据范围，不另扩文件系统支持 |

没有调用会探测介质的 `admin.data.collect` / 完整准入，也不执行 `DM_MPATH_PROBE_PATHS`。后者会真实读路径并可能标坏路径，不适合作为只读发现。只在 multipath 已加载且控制节点存在时查询接口；不主动加载模块、建立映射或改 sysfs。普通文件与运行 ELF 的读取可能产生正常文件 I/O，因此“只读”不等于完全零磁盘访问。

读取上限包括 256 个块节点、64 个展示对象、4096 个挂载、图深度 32、输出 2 MiB；文件读取也有边界。系统盘关系在完整的已限额图上计算后再截断显示。注册以外的 DM 表不查询；外部映射只取 sysfs 名称/UUID/依赖元数据。此命令按需退出，无新增常驻进程或健康期轮询；本轮没有重测资源峰值，不作新性能承诺。

## 数据与证据语义

JSON schema 1 的主要字段：

- `environment`：本次内核、管理代码附带的运行包记录、已加载 target、排队参数及竞争服务检查；未知支持策略单独保留。
- `volumes[]`：快照内编号、设备、型号、容量、系统/数据含义、挂载、消费者集合、关联保护组、`checks[]` 与 `assessment`。
- `groups[]`：登记名称/UUID、根/数据归属、当前节点，以及独立 `evidence` 和 doctor 当前观察。
- `checks[]`：`code/result/source`；结果为 `pass/fail/unknown/not_checked`。没有 `can_enable` 或一体化 `verified` 标签。
- `snapshot_id` / `snapshot_stable` / `issues`：标识本次观察、复读有无变化及缺失。稳定只表示两次采样一致，不保证采样间原子性，也不保证全部证据可读取。
- `configuration_stable`：分别表示 `relationships`、根候选、管理候选、当前命令运行包来源的前后比较是否通过；它不是配置合法性或产物完整性的总认证。

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| `preparation.state=installed` | 可信路径内收据记录已准备 | 产物整体完整性或当前已启动；`integrity` 保留未核对 |
| `restart=required` | 收据/manifest 记录的候选 ELF 哈希不同于当前 owner ELF；若要切换需冷启动 | 候选镜像已逐字节复核、只要重启就能成功、必须立即重启 |
| `binary_matches_dependencies_not_checked` | ELF 哈希相同 | 冻结库和基础工具也一致，或不需任何后续冷切换 |
| `current_runtime` / `current_boot_owner` | 本次启动的服务、owner、事务和就绪记录关联情况 | 文件系统、应用或全部下层 I/O 健康 |
| `topology=pass` | 已登记单路径 DM 表、USB 分区依赖、大小及排队标志符合当前检查 | 完整 LVM 布局、盘内身份或数据完整性；scope 明示仅 registered map/backing |
| `recovery_experiment=not_evaluated` | 本轮没有进行恢复实验 | 不能从历史报告提升为当前实例已通过实验 |

同一底层 PV 的根 LV/shared LV 合并呈现关联范围，不要求用户选技术模式；EFI、其他裸分区另列，不能据此称整块物理盘受保护。未挂载数据分区仍需身份及完整准入；已挂载裸分区拒绝在线改接，即便同时存在登记映射也不能掩盖二次挂载冲突。数据映射额外上层、整盘文件系统、缺少 USB 序列号、明确 swap 冲突等分别列原因。udev 仅是缓存，提示不支持的文件系统时也注明尚未核验介质。

登记无当前映射不自动判“待重启”；不可关联的 swap 路径、缺少 diskseq、权限不足等保留未知。登记非法或无法读取不视为已受保护。块节点图、挂载、swap 或 DM 表复读变化时，整体当前结论降级，嵌套 doctor 当前状态同步撤销。

协调者审阅指出首轮实现仅复读上述运行观察，未复读登记与候选配置；原报告的“登记表复读”表述不准确。本次已补上独立、有界的可信配置前后比较：

| 来源 | 比较内容与限制 |
| --- | --- |
| `ROOT_CONFIG` | 整个可信 JSON 的规范化内容摘要，包括首次不存在的状态 |
| `REGISTRY` | 最多 64 个名单成员；对本次读取的合法文件名分别比较整个可信 JSON 摘要，名单中新出现的文件只使快照失效，不临时扩展本轮采样 |
| 根/管理准备收据 | 两份收据的整个可信 JSON 内容摘要；缺失与不可读分开 |
| 当前管理代码的 `runtime/manifest.json` | 整个可信 JSON 内容摘要，变化时撤销包内核比较并清除输出中的该内核值 |
| 已安装管理候选来源 | 沿本次原收据复读 `manager_candidate()`：所选管理程序 SHA-256，以及 manifest 中用于候选判断的投影（native runtime、base/archive/binary 摘要等）；程序最多 8 MiB，manifest 沿用 Reader 的 256 KiB 限制 |

最多追踪 70 个来源（64 份登记加 6 个固定/候选来源），每个只复读一次，不重试、不加锁。只保留摘要，不复制整套登记；根候选哈希取自根收据，未扩展为根镜像/归档完整性扫描。管理候选 manifest 中未参与该投影的其他字段，不在此项比较范围内。

任一受观察配置变化、变不可读，或必须存在的登记/候选来源缺失时，`snapshot_stable=false`，撤销所有当前关联/运行/切换结论；受影响角色的准备收据状态改为 unknown，顶层与嵌套输出一致。登记关系失效还会撤销依赖登记的检查结果与嵌套 `mapping.identity_matches`，不保留旧 pass/true。其他角色未变化的收据仍可保留其收据状态，这不证明运行生效；原始组名等仅保留为失效采样的线索。

两次均确认不存在的可选配置视为一致缺失；不可读不能冒充不存在。内容前后相同但中间曾变化又恢复原值，以及最后复读后发生的变化，仍可能无法发现；也不保证跨多个来源的原子一致性。systemd/事务沿用 doctor 自身复读；udev 缓存、内核号、排队参数等不是本次新增的全局原子观察。输出不能作为稍后写入动作的授权或省略重新核验的依据。

仍未检查的 fstab/自动挂载策略、手工启动 multipathd、介质身份、全部依赖完整性明确展示。JSON 是本地未脱敏视图；分享使用既有 `export`，不把本地发现输出冒充脱敏导出。
