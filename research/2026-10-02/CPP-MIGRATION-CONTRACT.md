# C++ 迁移的行为约束

参考版本固定为 `e745e5e4b9cde4ffd21d03f6e45a491ca8400083`。此次迁移改变实现语言，不放宽已有的故障判断、登记边界和准入要求。

1. 每张映射只能有一个 owner。主进程和任何读写 helper 共享同一个 flock 的打开文件描述；截止时间、进程死亡和服务重启都不授予另一个写入者绕过该锁的权限。
2. 健康检查只读当前映射状态与 sysfs；不进行周期性 blkid/LVM 扫盘。内核 block uevent 提前唤醒，1 秒周期兜底，事件合并和恢复退避与参考版相同。
3. “当前实例消失或 DM 路径 F”仍是恢复入口。完成计数、在途请求数和疑似停滞只是观测，不直接授权换盘。
4. 每次新准入核验已登记 USB/分区身份、容量、几何、LVM 或文件系统元数据，并持有块设备 FD，比较节点、sysfs、dev_t 与 diskseq。重复身份、布局变化、活跃 dev_t 被新实例重用等歧义都拒绝。
5. 最终实例复核紧贴 load/resume 操作。load 意图先落在 RAM journal；一次 `resume --noflush --nolockfs` 提交，不增加独立的用户空间 suspend 窗口。提交后必须经过当前内核 `DM_MPATH_PROBE_PATHS` 和状态复核，才宣布恢复。
6. 控制器任意时刻最多有一个后台操作。worker、候选 FD 和原 owner 锁持续到结果转移或迟到结果清理完成。C++ 用 RAII 和共享所有权表达生命周期，不能依靠析构时无限 join。
7. 截止时间只停止新准入。旧 syscall 可能仍在 D 状态；接管等其锁释放后核对已知 active/inactive digest，先清除旧 inactive 表，再恢复/关闭无路径排队。不自动复用旧准入凭证，不因重启清除终态。
8. 保留同样的 JSON 登记/事务格式和 SHA-256 规范化结果，包括数字和 Unicode 序列化。C++ 原生异常只保留有界诊断，不在 RAM 故障路径加载 Python 源码。
9. 启动阶段、常驻运行、死亡接管和登记数据盘接入全部调用 C++ ELF。Python 继续承担冷态管理、人工救援、冻结对照与实验测试；这些用途不是另一个并行恢复 owner。
10. 文件系统和应用继续使用原映射、原挂载、原 FD。挂载计划由 systemd 实施；只读状态不擅自改为读写，文件系统既有错误不会被映射恢复自动抹除。

比较必须包含真实恢复 helper 的 CPU 和内存；只读观察器成绩不能列为完整恢复成绩。记录源代码/ELF/镜像散列和原始采样，分别给出稳态、事件风暴、恢复、重复恢复后的占用，并说明内核记账、虚拟化和窗口采样的限制。实机部署与源码推送是不同动作，本轮不替换实机运行包。
