# P0：保护启动失败与人工救援会话

2026-10-03，Ubuntu `7.0.0-34-generic`，x86_64。保护启动失败停止策略和人工救援会话改进已经实现，通过候选镜像的完整 QEMU 验收。实机现有 C++ Guard 的首次启动已另行核验，见 [实机记录](HOST-CPP-BOOT.md)；新策略的实机激活仍须下一次保护启动。

## 改动及职责

### 启动失败停止

原 `local-top`/`init-bottom` 的失败路径调用发行版 `panic()`；当前 Ubuntu 的 initramfs-tools 在没有 `panic=` 时会打开未认证 shell。该控制流是静态确认，不等同于动态攻击复现。

新保护镜像在 `/conf/conf.d/ram-rescue-guard` 设置 `panic=0`。项目自身的失败处理也在子 shell 内固定该值，调用发行版停机机制；如果停机函数返回或异常退出，外层保持阻塞，不能返回 `/init` 继续启动。测试覆盖 EXIT 与 HUP/INT/QUIT/TERM 信号。没有将失败改为绕过保护继续启动。

本机精简 initramfs BusyBox 没有 `halt` applet，因此构建 hook 明确校验并复制发行版完整静态 BusyBox 到 `/sbin/halt`，缺少能力时构建即失败。这个依赖属于早期 initrd，不是额外常驻 Guard。失败后需要用户重启并选择保留的普通 Ubuntu 入口排障，不自动重启循环。

内核命令行与引导菜单仍属于管理员信任边界：项目失败处理强制停机，但能修改启动参数的操作者可以影响发行版其他 `panic()` 路径。此项没有实现引导链认证、Secure Boot 策略或离线改盘防护。

### F9/F10 会话

认证继续使用发行版 BusyBox login。项目只配置会话，不自行实现认证算法或另起会话监控服务。实验确认当前 BusyBox ash 的 `TMOUT` 没有达到所需行为，所以认证后使用发行版 Bash，禁用 profile/rc 与环境钩子，历史不落盘、umask 为 077。

- 默认 `IDLE_TIMEOUT=900`：等待一条完整命令超过 15 分钟会退出，再次使用必须认证。这里是 Bash **提示符等待超时**，不按每个按键刷新计时，也不会中断运行中的前台恢复命令。
- 配置只接受固定数字键，`0` 禁用，`1..86400` 启用；不执行或 source 配置。重复、缺失、非法值直接拒绝。
- 未登录终端保持阻塞等待（`LOGIN_TIMEOUT=0`），避免闲置的两个 VT 定期重启登录进程。已有错误密码延迟与监督进程重试间隔保留。
- 新设密码要求至少 15 个可打印字符、UTF-8 不超过 1024 字节，允许普通空格和中文，不强制字符类别。拒绝 NUL/控制字符，防止长度检查通过后由工具截断。既有密码不改变，也不据此声明既有密码强度合格。

这是无人照管终端的会话卫生措施，不能约束已经登录的 root：root 可以改变超时、启动别的 shell。F9/F10 仍是共享宿主内核的完整 root 救援环境。

构建器将会话脚本、配置、Bash 和依赖覆盖进保护镜像，记录逐文件散列。凭据仍由原有准备服务在实际根系统可访问时复制到 RAM；公开镜像账户保持锁定。凭据复制之前就失去根盘，首次终端准备仍可能阻塞或拒绝，没有免密降级。

## 资源与兼容边界

常驻 C++ ELF 及全部运行库清单与已运行版本完全一致，ELF SHA-256 为 `72d9d550079b4f73e1954e13f99fa614826758c623eec1d3026aa22bc891b21f`。没有增加健康期轮询或后台进程，本轮也没有重新测量 CPU 均值/峰值，不能据此报告性能提升。

会话文件净增加 **1,447,770 字节（约 1.38 MiB）**，其中 Bash 为 1,446,024 字节；相关库原本已在 RAM 包内。早期 initrd 的完整静态 halt 工具为 **2,124,608 字节**。这些是文件负载，不是进程 PSS/RSS。实机保护 initrd 从 113,051,907 增至 115,058,369 字节，压缩产物差值 2,006,462 字节，不应简单等同于运行内存增量。

本轮仅验收当前 x86_64 Ubuntu 内核/工具组合，没有增加旧内核或其他发行版兼容保证。上游工具更新后必须重建、验证并重新进入新环境，宿主 apt 升级本身不会替换已冻结的 RAM 副本。
