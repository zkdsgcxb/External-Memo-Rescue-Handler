# EFI 相关代码审阅与整理

日期：2026-10-01。基线提交 `f1806f4`。本轮主要审阅、整理宿主安装工具、EFI 集成及其 VM 验证代码；另对共享 Guard 的职责和资源证据进行只读检查，未重写恢复状态机或改变已部署系统配置。

## 结构整理

- `guard/host_files.py` 集中宿主持久化文件工具，删除 enrollment/build/install 中重复的 SHA-256 实现；原子替换仍同步文件与父目录。EFI 不再为了两个文件函数导入整个根盘登记/恢复模块。RAM 运行时的有界日志写入职责不同，保持独立。
- `guard/efi_mount.py` 将检查备份、校验 VM、清理旧 fsck 状态、核对挂载、启用监听、写入状态和撤回配置分开。三个受管文件集中描述，安装和所有权检查使用同一列表；保留既有收据字段和命令行接口。
- `lab/guest/efi_probe.py` 从嵌入字符串中提取为正常 Python 源码；虚拟机内动作按方法组织，可以单独检查和测试。宿主 runner 分为输入检查、准备镜像、故障场景、验收和清理。
- 测试提取重复的配置清理及记录断言；保留身份、备份、维护锁、原生检查次序和失败撤回等行为验证。

## 审阅中修复的问题

1. **安装中断后的清理入口缺失。** 原来 `preparing` 状态既不能重新安装，也不能移除。现在允许从这个状态核验、撤除已写入且仍归本项目所有的文件。
2. **拒绝移除也改写记录。** 原来发现管理员改过配置之前，记录已被改为 pending。现在先完整核验所有权，再记录移除进度。
3. **次生错误影响原始故障定位。** 安装回滚失败会附加到原错误；VM 清理、哈希或 FAT 审计失败会保留在报告中，继续尝试其他收尾步骤。QEMU 未退出时禁止执行离线 FAT 检查。
4. **串口持续噪声绕过超时。** 改为整个请求共用一个截止时间和输出上限，失败请求也写入日志；guest 中必须成功的命令不再忽略退出码。
5. **实验输入路径核验不足。** 校验实际解析后的种子/构建镜像路径，拒绝通过父目录符号链接越出 `lab/work` 的输入。

VM 报告新增安装器依赖和 guest 源码哈希，启动与收尾均复核；保留原报告字段及 22 个验收项。这些变化没有改变 udev 规则、path unit 和 fsck drop-in 的生成内容。

## 验证结果

- lab 单元测试 **214 项通过**，其中 EFI 安装 **33 项**、VM 错误路径 **9 项**；RAM 救援测试 **15 项通过**。
- 完整 Ubuntu VM 的 **22 项验收全部通过**：包含快速重接、旧卸载与新设备到达交叠、fsck 重跑、失败限流及监听启用时关机。最终离线 `fsck.fat -n` 返回 0，原种子和受验源码未变，清理无错误。
- 三个生成配置与上一轮正式验收记录逐字一致；本机 EFI mount、原生 path 和 Guard 均 active。本轮没有重新安装、停止宿主服务或进行物理拔插。
