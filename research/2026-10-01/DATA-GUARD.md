# 独立 USB 数据映射扩展与验收

日期：2026-10-01。定位：给 Linux DM multipath 提供热插拔后的身份核验、路径恢复与失败处理。继续复用现有 Guard，扩展登记策略和实例接入，不建立第二套恢复状态机或磁盘管理器。

## 交付范围

- `guard/runtime/data_recovery.py` 增加普通文件系统分区身份策略，复用 USB 唯一候选查找；原 LVM 策略保持兼容。
- `Admission` 继续统一持有设备 FD、diskseq、期限、owner 和切换前核验。数据登记额外约束原分区起始扇区；文件系统策略核验 TYPE、UUID、PARTUUID，不把可变卷标作为恢复身份。
- `guard/runtime/data_guard.py` 只读登记已有单路径 DM 映射，拒绝根盘/系统盘、原分区挂载冲突、额外上层映射、swap、竞争控制器和不符合约定的映射表。
- `guard/data.py` 提供 `enroll/start/stop`。代码、登记和服务运行资料放入现有 RAM 环境，新增代码不覆盖运行中的根盘 Guard。临时 udev 规则排除裸分区桌面自动挂载并抑制 DM 扫描。
- 数据实例共用一份 20% 单核 CPU／20 ms 周期、256 MiB、零 swap 的 cgroup 上限；每实例另限 128 MiB。已有根盘配额独立保留。内核全局无路径 timeout 仅读取，不修改。

初次并发启动两个实例时，共享代码目录可能由另一启动器先完成发布；已修正为核验完整内容后复用。没有把目录存在本身当作正确版本的证据。

使用说明和当前接入约束见 [guard/DATA.md](../../guard/DATA.md)。本机没有选定第二块 USB 试验盘，因此本轮不部署数据实例，不修改实盘映射、挂载或启动配置。本轮结束时原根盘 Guard 与 EFI path 均 active，宿主没有 `/run/ram-rescue-data` 状态目录。

## 拔插与应用等待时间

测试设置了 0.2 秒等待，但 QMP 删除／添加和调度耗时使实际记录间隔更长；这不是精确的物理 USB 电气断联时长，也不是恢复完成时长。

| 观测 | 实测 |
| --- | ---: |
| 首次 ext4 删除完成至重新添加 | 0.252 秒 |
| 共同拔插时 ext4／FAT32 间隔 | 0.352／0.312 秒 |
| FAT32 删除至换回正确盘，包含错误盘核验 | 2.376 秒 |
| ext4 最长一次写入＋fsync＋直接读取 | 2.201 秒 |
| FAT32 最长一次写入＋fsync＋直接读取 | 4.596 秒 |
| 同时运行的根盘工作负载最长 fsync | 0.107 秒 |

ext4 确认 59 条、241,664 字节；FAT32 确认 36 条、147,456 字节。本轮证明了这些工作负载在等待后继续完成，没有证明零延迟、任意应用无感，或真实硬件掉电时未落盘缓存不丢失。

| CPU 100 ms 采样窗口峰值 | 0.923% |

实际 `cpu.max = 4000 20000`，`memory.max = 268435456`，`memory.swap.max = 0`。CPU 窗口峰值不是指令级瞬时峰值；这段短时 VM 健康采样不代表长期实盘表现，也没有测得恢复阶段的资源曲线。

## 回归与保留边界

`lab/tests` 250 项、`ram-rescue-demo/tests` 15 项通过，合计 **265 项**；`git diff --check` 通过。新增测试覆盖文件系统身份错误、克隆序列号歧义、分区移动、实例变化、系统盘拒绝、挂载／swap／fstab 冲突、精确 udev 匹配、启动竞态以及失败后不清空旧事务。

- exFAT 已有准入策略与单元测试，本轮没有 exFAT VM 或实盘拔插验收。NTFS、LUKS、额外 LVM、整盘无分区布局、stock multipathd、多路径 SAN 不在数据模式当前接入范围。
- 需要预先经稳定 DM 挂载；事后启动 Guard 不能撤销已经送到文件系统或应用的错误，也不能把正在使用的裸分区在线改接。
- 每个数据实例有独立 owner、事务和截止时间；目前仍为每盘一个 Python 进程，各自接收块设备事件。合计 cgroup 限额控制资源上限，并没有把它改成一个多盘常驻进程。
- 同一映射的 `stop` 为终止本次保护，不提供清空事务后直接重启的捷径。内核下层永久阻塞、旧操作未释放 fence 时仍可能无法立即完成接管。
- USB 序列号和盘内 UUID 不是密码学认证；完全克隆的身份不能据此区分。新磁盘实例复用当前活动后端 dev_t 时，原有保守拒绝逻辑继续生效。
- 本次新增运行代码没有替换实机当前根盘 initrd；新的根盘构建仍应按原安装流程另行验收。
